# 색 계산 권위 데이터 + 역설계한 정확 알고리즘 (qtColor.ts 핀)

Qt의 `QColor.lighter(f)`/`darker(f)`는 **Qt C++ 라이브러리 내부 계산**이라 옛 파이썬 코드엔 결과 값이 없다.
Pro 1.2를 실제로 돌려 캡처한 권위 출력 2건으로 **정확한 알고리즘을 역설계·검증**했다.

## 권위 데이터 (그라데이션 태그 = `linear-gradient(135deg, lighter(120), darker(120))`)

| 기준색(base) | lighter(120) | darker(120) | 캡처 |
|---|---|---|---|
| `#cbd5e0` (연한 회청) | `#f5faff` | `#a9b1bb` | r02-tag-styles |
| `#e74c3c` (진한 빨강) | `#ff6858` | `#c03f32` | r02b-tag-vivid |

## 역설계한 알고리즘 (두 샘플로 검증됨)

RGB → HSV(정수) → V 스케일 → RGB. **H, S는 보존, V만 스케일.** `.name()` = 소문자 `#rrggbb`.

- **darker(f)** (f≥100): `V = V * 100 / f` (정수 나눗셈). H·S 그대로.
  - 검증: `#e74c3c`(V=231) → V=231*100/120=192 → `#c03f32`(max=192) **정확 일치** ✓
- **lighter(f)** (f≥100): `V = V * f / 100`. **만약 V>255이면 → `S = S - (V-255)` (255 스케일에서 채도를 넘침만큼 깎음), 그 뒤 V=255.**
  - 검증: `#e74c3c`(V=231,S≈189/255) → V=277>255, overflow=22 → S'=189-22=167, V=255 → `#ff6858` **정확 일치** ✓

## ⚠️ 핵심 함정 (코드만 봐선 절대 못 봄)

"색을 120% 밝게"라는 말에서 **아무도 추측 못 하는** 동작: 밝기가 한계(255)를 넘으면 Qt는 **채도를 넘침만큼 깎는다**(`s -= v-255`). 그래서 밝은 색일수록 그라데이션이 살짝 희끄무레해진다.
- 순진한 포팅(RGB×1.2, 또는 채도 보존 HSV)은 **다른 hex**를 내고 테스트 없이는 안 보인다.
- 정수 반올림까지 Qt와 1바이트도 안 틀리게 맞춰야 함 → 위 골든 값이 최종 검증 오라클.

## 포팅 메모
- Qt HSV는 H:0-359, S/V:0-255 정수. JS 포팅 시 Qt의 정수 나눗셈/반올림을 그대로 재현.
- 추가 검증 원하면 채도 중간색 1-2개 더 캡처(연한색 #cbd5e0는 ±1 반올림 케이스라 정수 규칙 확정에 유용).

## ✅ 구현 상태 (2026-06-16)

- 첫 시도(8비트 근사)는 채널당 ±1 어긋남 → 골든이 즉시 0/4로 잡아냄.
- Qt 내부 정밀도 재현으로 해결: **8→16bit(×257), HSV의 S/V는 0..65535·H는 0..35999, V 스케일은 정수, 16→8bit는 round(c16/257).**
